# Excel Reconcile · 两表核对工具

在本机核对 Excel / CSV 中的订单、供应商和金额，导出可追溯到原始行的差异报告。

这是实际可运行的个人作品，开发有 AI 辅助。仓库只包含模拟练习数据，不包含雇主、客户或个人隐私数据。它按公开规则进行确定性核对，不调用大模型，不训练模型，也不上传业务数据。

## 能做什么

- 两表金额差异、单侧缺失和供应商不一致检查。
- 重复编号单独列出；可选择先待确认，或按编号汇总金额。
- 支持多列组合编号，例如「订单号＋行号」，无需手动拼接。
- 空编号、空金额、无效金额、空供应商和公式字段提示。
- 保留A/B源数据行号，输出核对摘要、差异清单、全部核对、重复编号、数据异常五个工作表。
- `.xlsx`、UTF-8 / GB18030 编码的逗号分隔 `.csv`；可选表头行。
- 12组可重复生成的样本，共21,810个业务编号场景，附逐项标准答案。
- 浏览器操作或JSON配置批量运行。仅监听本机 `127.0.0.1`。

## 安装和运行

需要 Python 3.10 或以上。安装 Python 后下载仓库并解压，打开终端进入项目文件夹。

macOS / Linux：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python reconcile.py
```

Windows：

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python reconcile.py
```

首次配置后，macOS可双击 `start.command`（必要时运行 `chmod +x start.command`），Windows可双击 `start.bat`。首次运行会自动生成练习样本和标准答案，然后打开浏览器；终端保持运行。结束使用时在终端按 Control+C。

不想自动打开浏览器：`python reconcile.py --no-browser`；固定端口：`python reconcile.py --port 8765`。固定端口若被占用，请换端口或使用默认自动分配。

## 三分钟试用

1. 在页面上选择「入门：常见差异」，点击「载入样本」。
2. 确认编号、供应商、金额列；默认模式为重复编号待确认、容差0.01。
3. 点击「开始核对」，下载结果，逐项查看差异清单和异常源行。
4. 点击「下载标准答案」，打开Excel中的标准摘要和逐项答案。另附机器可读JSON，`strict` 是默认模式，`sum` 是汇总模式。
5. 改成「按编号汇总金额」再运行：正常拆分订单应一致，整行重复录入仍有金额差异。

导出报告不等于核对已通过。待核查项、无编号行、业务口径都需处理后再判断。

## 练习路线

| 样本 | 业务编号场景数 | 练习重点 |
|---|---:|---|
| 01_intro | 10 | 入门分类和源行追溯 |
| 02_clean | 2,000 | 正常匹配及记录顺序变化 |
| 03_amount | 2,000 | 定位金额差额 |
| 04_missing | 2,000 | 两侧分别缺失记录 |
| 05_duplicates | 1,000 | 重复录入不能靠汇总修正 |
| 06_split | 1,000 | 订单多行的汇总口径 |
| 07_supplier | 1,000 | 供应商变化和同编号多供应商 |
| 08_dirty | 1,000 | 空编号、空金额和无效字段 |
| 09_tolerance | 500 | 0.01容差的边界 |
| 10_refunds | 1,000 | 退款、括号负数、千分位 |
| 11_identifiers | 300 | 前导零和大小写 |
| 12_large | 10,000 | 混合场景与规模验证 |

一个业务编号场景可能拆成多行，或因为编号不同而产生两个核对编号。21,810不是订单源行数或核对编号并集数。

所有样本由 `generate_samples.py` 使用固定种子生成，首次启动会自动生成全部Excel文件和逐项标准答案。标准答案由预先声明的注入场景生成，**不调用核对引擎**，避免把工具自己的结果当答案。它们用于练习和规则回归验证，不能代表真实行业数据的全部复杂性。

重新生成：

```sh
python generate_samples.py
```

使用不同种子扩展练习时，可调用 `generate_samples.build(count, scenario, seed)`，再用 `write_xlsx` 保存。默认样本种子和每笔答案在各目录的 `answer.json` 中。

## 批量核对

每个样本文件夹包含 `config.json`，源文件路径相对于配置文件：

```sh
python reconcile.py --config samples/03_amount/config.json --output results/金额核对.xlsx
```

配置中 `key`、`supplier`、`amount` 为从0开始的列索引。多列编号用 `keys: [0, 1]` 替代 `key`。`header` 从1开始。`mode` 为 `strict` 或 `sum`；`tolerance` 是金额绝对容差。

## 规则与限制

- 输入必须为未加密的 `.xlsx` 或逗号分隔 `.csv`。不支持 `.xls`、PDF、多层合并表头、自动识别财务口径。
- 单文件20MB，单表扫描最多100,000行，表头在第1—100行；Excel解压总大小不得超过200MB。大规模输入耗时取决于电脑性能。
- 编号与供应商仅去首尾空格，区分大小写。文本001与数字1不相同。Excel存成数字后丢失的前导零不能自动还原。
- 默认按编号匹配；如一个订单有多行，应选择组合编号或在确认业务规则后选择汇总模式。
- 同编号多个供应商不判为一致；供应商名与供应商编码不会自动对应，需先统一口径。
- 金额支持正常数字、逗号千分位和括号负数；空值不当作0。金额绝对值须小于1万亿元、最多6位小数。用Decimal比较，不在比较前隐式四舍五入。
- Excel核对字段里的公式不会自动执行。请在源表副本中粘贴为值。其他列公式不参与计算。
- 差额为A-B；绝对差额大于容差才标记金额差异。金额、币种、含税口径、日期范围由使用者确认一致。
- 金额合计包含有有效数字金额但编号缺失的行，不能当作成功匹配金额。汇总不删除重复行，不区分重复录入与正常分批。
- 文件在本机服务中处理，报告由浏览器下载；不修改原文件。CLI禁止输出覆盖输入文件。
- 这是本机工具，未经重新设计与审查，不应直接作为公网多用户服务部署。
